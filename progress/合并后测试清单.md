# 合并后测试清单

## 简介

本文列出 PR #77 合并后，在开发机上仍需完成的测试。测试基底是 main 最新头 `41acbe2`，含 PR #77 的 P1 六项修复（D8-01、D8-02、D8-03、D8-06、D8-11、D8-16），以及 PR #79、PR #80 的 compose 转义与 worker 解堆批。

合并通过 CI 不等于缺陷闭合。D8-02、D8-03 的 compose 改动在提交方环境无 Docker，未做实起验证。缺陷 5、缺陷 6 只有本文第二、第三部分的任务全部通过，才能写闭合。

测试数据一律使用合成样本，不使用企业原文，不使用生产数据。GATE-P0-001 至 008 仍全部未验证，本文测试通过不等于正式验收通过。

## 环境准备

开发机为 Arch / Omarchy 笔记本，Python 3.12，Docker 与 Compose 可用。依赖版本以联调报告为准：PostgreSQL 16.4，Qdrant 1.12.4，Redis 7.4.1，对象存储为 pgsty/silo RELEASE.2026-09-16。

测试前先拉取 main 最新头，确认头提交为 41acbe2，再启动依赖服务。compose 命令需带 `--env-file ops/compose.env.example`，否则必填变量缺失会直接报错。

## 测试任务

### 应用服务启动

- 任务 1：compose 渲染检查。
  - 步骤：运行 `docker compose --profile app config`，检查 api、worker 的环境变量。
  - 预期结果：环境变量中能看到 `PIVOT_BM25_K1` 与 `PIVOT_BM25_B`。
  - 结果记录：通过（v2.0：`docker compose --env-file ops/compose.env.example --profile app config` 退出码 0、无告警、350 行；api 与 worker 均含 `PIVOT_BM25_K1=1.2` 与 `PIVOT_BM25_B=0.75`，另含 `PIVOT_QDRANT_DISTANCE=Cosine`、`PIVOT_QDRANT_ENSURE_COLLECTION=1`；web `PIVOT_API_ORIGIN=http://api:8000`）。
- 任务 2：应用服务启动。
  - 步骤：运行 `docker compose --profile app up -d`，观察各容器状态。
  - 预期结果：qdrant 由 unhealthy 转 healthy，api、worker、web 均启动，不再卡在 `depends_on healthy`。
  - 结果记录：部分通过（v2.1：qdrant、api、worker、web 四容器均 `Up (healthy)`，worker `/healthz` 200、Celery 5.5.3 就绪，D8-17/D8-18/D8-05 实证闭合；但 web 镜像内 `/api/v1/*` 全 404，见 D8-19）。
- 任务 3：健康检查。
  - 步骤：调用 `/healthz` 与 `/readyz`。
  - 预期结果：`/healthz` 返回 200，`/readyz` 中 postgres、minio、qdrant、redis 四项全为 true。
  - 结果记录：部分通过（v2.1：api 四项全 true，worker `/healthz` 200 且 require 模式通过，web `/login` 200 且容器 healthy；但 web 到 api 的反代为 404，健康检查覆盖不到该路径）。
