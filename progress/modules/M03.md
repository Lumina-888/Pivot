## 2026-10-20 ND-AGENT-04 S5：04-F 真实 PostgreSQL 故障测试矩阵

- 基线 main `c4eb826`。环境分工经 Owner 确认：开发验证在本机自建 PostgreSQL 先行（本轮用 pip 的 postgresql-binaries 16.15，与 CI 的 postgres:16 对齐），正式验收环境由 Owner 后定。本条是 ND-AGENT-04 的最后一个切片。
- 重大发现（本切片的核心产出）：在真实 PostgreSQL 上首次完整执行迁移链时发现，`alembic upgrade head` 日志显示六个版本全部执行，实际只落地到 `1ff9fb811713` 与下一版的两张表，`run_leases`、`provider_attempts` 等后续表静默丢失，进程退出码仍为 0。根因是迁移 `1ff9fb811713` 与 `102d30d04451` 中六处 `with op.get_context().begin_transaction():` 包装：PostgreSQL 事务型 DDL 下该块退出会提前提交外层迁移事务并使 alembic 事务记账错位，其余迁移在收尾时被回滚。SQLite 上该写法无害，所以迁移测试自 2026-10-12 起一直全绿而无人察觉；真实 PG 联调此前未做（AGENTS.md 亦有记录）。若按原迁移上生产，应用启动后将在缺失的表上报错。
- 修复：去掉上述六处事务块包装，方言条件索引逻辑原样保留（两文件各处已加注释说明）。修复后在 PostgreSQL 16.15 上实测：upgrade 到 head 共 24 张表且版本正确，downgrade 到 base 干净，再 upgrade 仍一致；SQLite 的迁移测试（test_M03_migrations）继续通过。已应用过旧迁移的 SQLite 环境不受影响；PostgreSQL 上旧迁移从未成功落地过，不存在半成品库需要善后。
