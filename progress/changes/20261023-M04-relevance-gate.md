# ADR-014：相关性门禁与单文档配额

- 状态：accepted（dev-staging）；依据 Owner 2026-10-23 批准的端到端方案线三。
- Accountable：M04；Contributors：M05 问答结局、M11 装配。
- 基线：main `1c789fc`。
- 需求：FR-RAG-008（相关性门禁、重排候选池与单文档配额）。

## 背景

- 检索层实测（PR #14）与 ND-P0-03 真实嵌入复跑（PR #26）结论一致：企业集拒答两层全灭，合成与受控嵌入、真实嵌入、带与不带重排四种组合下结论不变。根因不在嵌入模型，而在检索链没有任何相关性下限。
- 失败形状已定性：unauthorized 层授权过滤正常、禁止块零漏出，失败是拿授权范围内的无关语块硬答；no_answer 层的漏出是诱饵语块被当作证据。两层共同点是无关语块进入证据集后，上层只在检索返回空时才拒答。
- 重排分数此前只用于排序与截断，进入证据筛选前即被丢弃；重排候选数与最终证据数绑死（同为 evidence_limit），多语块问题里互补语块会被挤出前五（ND-P0-03 合成集带重排 108/120，12 例全为 multi_span）。

## 决策与边界

- `RetrievalPolicy` 增加四个可注入字段，默认全关，关时行为与现行逐位一致：`rerank_floor`、`dense_floor`、`rerank_pool`、`per_doc_cap`。数值仍属 TBD-P0，本 ADR 不冻结任何生产值；标定与候选值产出为线三 D，冻结仍走 DR-010。
- 门禁位置在 `RetrievalService.retrieve` 的证据筛选处，LlamaIndex 问答路径、原生路径与文档检索共用同一漏斗，一处生效。
- 通过规则为任一强信号过线：重排分数达到 `rerank_floor`，或 dense 分数达到 `dense_floor`。RRF 分数只反映名次，不作相关性信号。
- 信号可用性按实测处理：某条已配置下限的信号对该语块不可用（重排未配置、调用失败、或语块未被打分）时，该分支不参与判定；若已配置下限对该语块全无可用信号，语块放行。供应商降级时退化为门禁前行为，不凭空制造空结果。此口径与 FR-RAG-004 的降级哲学一致。
- 全部候选被门禁淘汰时，检索返回 `empty`，既有拒答分支（编排器的 refuse、智能体的 insufficient_evidence）随之生效，不新增结局种类。
- 重排候选池与最终证据数解耦：`rerank_pool` 控制送入重排的返回上限，未配置时等于 `evidence_limit`（现行行为）。最终选择按 `per_doc_cap` 限制单文档入选语块数，未配置时不限制。
- 授权口径不变：门禁只在已通过实时授权与过滤的候选上工作，不放松任何过滤；证据分数的对外形状不变（仍为 RRF 分数）。

## 与既有记录的关系

- 落实 DR-002 的根因结论（拒答失效与嵌入模型无关，缺的是相关性下限）。
- 线三 D 将以双金标集做分数分布标定并四组复跑，产出 DR-010 候选值；本 ADR 只立机制，不立数值。
- GATE-P0 状态不变。

## 未决事项

- 线三 D（2026-10-23 已完成，证据 evidence/golden-set-eval/line3-d-eval.md）：标定与四组复跑完成，DR-010 候选为 rerank_floor 0.3、dense_floor 0.65、rerank_pool 12、per_doc_cap 不启用。企业集内容层 96 / 96、no_answer 两套集全过且泄漏清零已达成；unauthorized 企业集与合成集 multi_span 两项未达成，根因分别见证据 §4.1 与 §4.2（前者定性为答案层议题，后者为合成集构造产物）；ag-005、ag-006 检索层未翻正（证据收窄到 1 块），见证据 §5。生产默认装配暂不改动，候选值随 DR-010 冻结一并接线。
- 残余风险（已兑现并定性）：授权相邻语块的重排分数与真答案完全交叠，分数门禁不可分；答案层相关性判定（收尾器核验所问内容是否被证据支撑）建议单独立项，与 05-D 业务复核集重跑合并评估。
