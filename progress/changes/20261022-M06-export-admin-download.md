# ADR-012：导出下载的管理员访问

- 状态：accepted；依据 Owner 2026-10-22 会话决策。
- Accountable：M06；Contributors：M01 授权实现。
- 基线：main `3acdaf4`。
- 需求：ND-GAP-04 的授权口径；属权限语义变化，按 SPEC 0.6 登记本 ADR。

## 背景

- 导出授权的既有实现对管理员设专门拒绝：导出本人可查看与下载，非本人普通用户返回「资源不存在」，管理员则明示无权。该口径使管理员无法为运维与支持目的取得用户导出内容。
- ND-GAP-04 补齐签名下载消费者时，该口径与工单原定的「本人或管理员」目标冲突，须由 Owner 拍板。

## 决策与边界

- 导出查看与下载对两类身份放开：导出本人，以及任意管理员。
- 非本人普通用户的行为不变：返回「资源不存在」，不泄露导出是否存在。
- 本决策只改导出授权（`authorize_export`）。以他人会话新建导出的授权（`authorize_conversation`）不变，管理员仍不得以他人会话新建导出。
- 管理员的查看与下载同样写 `export.download` 等审计事件。按 ND-GAP-02 分级，`export.` 前缀属安全关键事件，审计落库失败即拒绝操作（fail-closed），管理员访问全程留痕。
- 实现落点：`security/rbac.py` 与 `http/memory.py` 两处 `authorize_export` 同步修改，单元测试替身保持一致口径。

## 残余风险

- 管理员自此可取得任意用户的导出内容，隐私边界较此前放宽。此为 Owner 明确接受的运维需要，前提是审计留痕与 fail-closed 不被绕过。
- 如后续需收紧，撤销本 ADR 并恢复三处实现与相应测试即可，无数据迁移。
