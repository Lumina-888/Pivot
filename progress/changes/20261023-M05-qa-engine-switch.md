# ADR-013：问答引擎开关与 Agent 生产装配（W1）

- 状态：accepted（dev-staging）；依据 Owner 2026-10-23 批准的端到端方案线一。
- Accountable：M05；Contributors：M11 装配、M04 检索。
- 基线：main `e6f1e6d`。
- 需求：FR-AGENT-009（模型适配与用量可追溯）、FR-AGENT-001（真实 LangGraph 闭环的生产装配）。

## 背景

- ND-AGENT-04 与 ND-AGENT-05 已交付 LangGraph 智能体图、模型适配器与评测装配，但图从未接进 API 生产装配：网站问答一直由确定性编排流水线执行，评测装配只存在于测试与运行器脚本。
- 端到端方案线一要求把智能体接进生产，且切换必须可控、可回退：默认行为不变，智能体按配置启用，启用失败要在启动期暴露而不是首个问题时暴露。

## 决策与边界

- 新增问答引擎开关 `PIVOT_QA_ENGINE`，取值 `pipeline`（默认）与 `agent`。默认装配与现行行为完全一致，编排流水线继续服务 HTTP 问答。
- `agent` 时，启动装配按评测装配的同一形态组装智能体运行器：`AgentModelSettings.from_env()` 构建主备模型（ADR-011 选型，配置缺失或不完整在启动期报错）、预算策略、结构化收尾器（与编排共用同一草稿生成器）、问答检索器（与编排共用同一实例，含 LlamaIndex 默认后端）。
- 预算策略的开发期数值与评测基线一致：单 Run 模型调用 10 次、工具调用 20 次、改写 3 次、超时 60 秒。经 `agent_budget` 注入点可替换。生产冻结仍属 DR-010，本 ADR 不冻结任何生产数值。
- 模型尝试记录经 attempt_sink 汇入运行器的 attempts 列表，作为 W2 持久化对账的接缝。注入模型（测试）自带 sink 时以注入侧为准。
- W1 只做装配与开关。智能体结局到 Run 状态机与 SSE 的对接、尝试记录落账、澄清恢复接线为 W2。`agent` 装配完成不等于执行切换，HTTP 问答在 W2 前仍走流水线。
- 授权、证据释放与外发门禁口径不变：图内工具只经问答检索器取数，逐条实时授权与 OutboundGuard 沿用 ND-AGENT-04 与 05 的既有实现。

## 与既有记录的关系

- 线三（拒答与重排修复）的 ADR 编号顺延为 ADR-014。
- GATE-P0 状态不变；DR-010 仍未冻结。
