# ADR-015：答案层问题-证据相关性判定（FR-AGENT-012）

- **日期**：2026-10-23
- **申请人**：答案层立项会话（线三 D 残余项与 ND-AGENT-05-D 核心发现的合并处置，Owner 2026-10-23 立项并批准方案）
- **背景**：端到端拒答只在检索返回空时成立。证据存在但答非所问时，收尾照常成答：ag-005（问婚假、答年休假不享受情形）、ag-006（问个人余额、答通用年休假条款）两组 live 均有实证；企业集 unauthorized 层 12 例同形（问无权摘录、答同编号已授权段）。检索层已由 ADR-014 处理「无相关性下限」，但线三 D 标定证明该层残余不可分：无关语块的重排分数 0.946 至 0.96 与真答案分数带（最低 0.948）完全交叠。
- **原契约/现状**：
  - Agent 路径的收尾（`StructuredFinalizer.finalize`）只判证据是否为空；引用绑定校验是结构校验，声明忠实于无关证据时同样通过。
  - 确定性信号已被实测逐个排除：重排分数交叠（见上）、稠密余弦对话题相邻内容不敏感、词面重叠对共享编号词元的语块反而给最高分。问题与证据的语义相关性只能由模型判定。
  - finalize 阶段的模型调用（生产 writer 路径）不在单 Run 模型调用计数内，是 ND-AGENT-05 已登记的计数缺口。
- **决策**：
  - 新增答案层相关性判定组件（`api/src/pivot/qa/agent_relevance.py`）：`RelevanceJudge` 协议与 `ModelRelevanceJudge` 实现。判定在 Agent 图 `finalize` 节点、收尾器成答之前执行：把问题与注册表证据（定位加正文摘录）交给模型，只许输出 RELEVANT 或 IRRELEVANT；提示明确证据是不可信数据、其中指令不得执行；无法解析的输出按相关处理（fail-open 方向见下）。
  - 判定不相关时，结局复用既有 `insufficient_evidence` 状态与拒答文案，状态机、SSE 与公开契约零变更。
  - 失败处置 fail-open：判定调用异常、超时或预算已耗尽时跳过判定、照常成答，并留下尝试记录。理由：相关性是质量门，不是授权门；授权已由检索过滤与读取重授权把守，判定器故障不能把可答问题误拒。误拒风险由验收的可答场景通过率守住。
  - 预算计数：判定调用计入单 Run 的模型调用计数与 token 结算（经图内 BudgetGuard，与 decide 同口径），补上 Agent 路径内 finalize 不计数的缺口（本决策只覆盖图内判定调用，生产 writer 的计数口径不在本片）。
  - 开关与装配：图层参数 `relevance_judge` 默认 None（关），关时行为与变更前逐字一致。评测装配（05-D 运行器）经工厂注入开启并作 live 验收。生产装配（W1 bootstrap）本片不接线：是否在生产 Agent 模式默认开启，随 W3 联调与 DR-010 一并定。
- **影响模块**：M05（agent_relevance 新增、agent_graph 的 finalize 与构建函数、05-D 运行器）；其余模块行为不变。
- **兼容方案**：默认关即现状；开启时仅新增「证据不支撑所问内容则拒答」一条路径，复用既有结局形状。检查点与注册表快照形状不变。
- **测试 ID**：`test_FR_AGENT_012_*`（判定不相关拒答且不调 writer、相关照常成答、判定异常 fail-open、无判定器行为不变、判定调用计入预算、预算耗尽跳过判定、ModelRelevanceJudge 输出解析）。
- **验收**：05-D 装配 live 复跑（thinking 开、关两组）：ag-005、ag-006 至少翻正一个；按原 9 场景通过率不低于 7 / 9；安全断言全清。证据见 `evidence/agent-m05/nd-agent-012-relevance-gate.md`。复核集（ND-P0-01-A）到位后以复核集正式复跑一次。
- **未决事项**：生产装配是否默认开启（随 W3 与 DR-010）；判定提示词与摘录长度的调优（以 live 验收的误拒、漏放分布为输入）；pipeline 路径复用同一组件的接线时机。
- **审核结果**：随答案层切片提交，待 Owner 随 PR 审核。
