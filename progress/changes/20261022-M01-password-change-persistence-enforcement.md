# ND-GAP-03 首次改密落库与服务端强制（2026-10-22）

## 背景

`must_change_password` 标志此前只存在于领域对象：创建用户与管理员重置密码时置真、改密时置假，但 PG 用户目录适配明确不落库（读出恒为假、写入丢弃），PG 装配下首次改密强制实际不存在；后端也无任何拦截，改密全靠前端自觉。本变更按 Owner 2026-10-22 决策补齐落库与服务端强制。

## 决定与口径

1. **落库**：`users` 表新增 `must_change_password` 布尔列（非空，服务端默认 false），迁移 `45f1c8bda305` 接在 `14fcf89c4926` 之后；存量用户默认 false，不强制改密。用户目录适配改为读写真实列。
2. **服务端强制**：`AuthService.authenticate()` 在令牌、状态与版本校验通过后检查该标志：置真时抛 `AUTH_PASSWORD_CHANGE_REQUIRED`（HTTP 403），一切业务路由经此咽喉统一拦截。仅改密流程内部调用以显式参数 `allow_password_change=True` 放行。
3. **登录响应**：登录与刷新响应体新增 `must_change_password` 字段，供前端据此跳转改密页；这与后端的 403 拦截是双保险，不以前端跳转代替服务端强制。
4. **放行清单**：只有改密接口本身。刷新令牌不经 authenticate，置真用户可续期令牌但调不动任何业务接口，不构成绕过；登出同样被拒，置真令牌自然过期即可，属可接受口径。管理员账号被重置密码后同样置真，无例外后门。
5. **初始密码**：维持管理员创建时设定、线下告知的现行方式，不新增邮件或链接发放通道。

## 不变

密码策略（长度、复杂度）与哈希口径不变；`token_version` 语义不变，改密仍经 `_rotate_password` 轮换版本、清零标志并吊销刷新会话；管理员重置仍在轮换后复置标志。
