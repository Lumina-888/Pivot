## 背景与范围

`test_NFR_OBS_compose_staging_env_is_gitignored` 把 `.env` 或
`ops/compose.staging.env` 在工作区存在当作失败。Runbook 明确要求创建
Git 忽略的本地 `.env`；因此该断言混淆了运行配置与版本化密钥。
连续几轮全量回归的唯一失败已在 main 基线上复现。

只修改 M11 staging 测试及进度/证据。不读取、删除或覆盖用户配置，
不改变 `.gitignore`、业务实现、公开 API、CI、依赖或 Agent DoR。

## 修正契约与安全边界

- 两个既有私有路径必须不在 Git 索引中，包括强制暂存但未提交的文件。
- 两个路径必须实际匹配仓库 `.gitignore`；仅注释包含文件名不算保护。
- 文件存在与否不影响判定；不读取其内容。
- 使用 Git 原生匹配与索引查询，不自写忽略语法解析。
- 不依赖用户全局忽略文件或 `.git/info/exclude` 掩盖规则缺失。
- 模板内容、供应商密钥、CI 不启动 Compose 等既有检查保持。
- Git 命令失败必须报错，不跳过或降级放行。测试环境须有 Git。

## 测试与兼容

沿用已有 staging 测试边界，使用独立临时 Git 仓库覆盖合法配置存在/不存在、
强制暂存任一私有路径、移除任一路径忽略规则、注释伪规则及本地排除规则。
先验证正向临时仓库在旧断言下失败，再修改检查并跑受影响组与分组回归。

不触发需求级 ADR：密钥永不入库语义未变；无公共字段、权限、状态机、
引用/删除或模型/检索配置变更。不解除 02-A/B/C/03-A/04-A 签认阻断，
DR-010/011、TBD-P0 与全部 GATE 状态保持。最终验证见本切片证据。
