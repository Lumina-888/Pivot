# ADR-018：文件夹与跨部门项目

- 状态：已接受；Owner 2026-10-24 批准。
- Accountable：M01；Contributors：M02、M03、M04、M10。
- 基线：main `da89c40`（P1-1 全部落 main；P1-2 已接受，ADR-017）。
- 需求：FR-RBAC-004 的 P1-4 部分。
- 依据：ADR-016；ADR-017；Owner 2026-10-24 会话决策。

## 背景与范围

P1-1 已经落地库级隔离。文档只归属一个库。库是公共库或部门库。用户可见库是公共库加所属部门库之并集。检索按库分集合执行过滤。管理 API 与审计已经覆盖部门与成员变更。

P1-2 已经定下例外与临时授权。文档级例外可以破例共享单篇文档。临时授权可以带到期时间。到期自动收回。续期在到期前直接改到期时间。Q1 至 Q4 均已定。

P1-4 补两块能力。第一块是文件夹。部门库内再分项目文件夹。第二块是跨部门项目。项目等于独立项目库。两块共用库模型与审计机制。

本稿不含审批流。发布审批与库间移动审批随 P1-3 设计。前端页面不在本稿范围。文件夹树交互细节列为开放问题。嵌套文件夹不在本稿范围。文件夹只做单层。按操作拆分不在本稿范围。只读含下载导出已经由 Owner 确认。

文件夹不取代例外。例外按文档授权。文件夹按组授权。两者共存。部门目标例外仍只归总管理员。规则见 ADR-017 Q4。

## 决策 D1 层级

层级已经由 Owner 定下。本节照录，不改动。

层级是总管理员、部门管理员、项目负责人、员工成员四级。总管理员拥有所有权限。部门管理员拥有本部门所有权限。项目负责人拥有项目级权限。员工成员按角色消费。

任命链为一级任命下一级。总管理员任命部门管理员。部门管理员任命项目负责人。项目负责人管项目成员。一人可任多个项目负责人。负责人人选不限本部门。任命权在所属部门管理员。

部门主管与项目负责人加人无须总管理员审批。加人包括本部门成员与外部门成员。控制手段是审计留痕。控制手段还包括总管理员全局可见。总管理员保留一切权力。日常流程走层级。紧急时总管理员可以直接干预任何一级。

## 决策 D2 部门管理员全可见

部门管理员全可见已经由 Owner 定下。本节照录并划清边界。

部门管理员可见公共库。部门管理员可见本部门库全部文件夹。部门管理员可见本部门创建的项目库。可见范围不依赖项目成员身份。部门管理员想看项目文档，无须加入项目。

部门管理员不可见其他部门的库。部门管理员不可见其他部门的项目库。未分配文档仍只归总管理员。部门管理员看不了未分配文档。

部门管理员在本部门范围内永远全权。文件夹角色限制不住部门管理员。只读文件夹对部门管理员同样全权。管理权与可见权在部门范围内统一。

透明性要求必须落实。项目页必须明示一句话。明示内容是所属部门管理员可见全部项目文档。外部门成员加入项目之前应当知晓。知晓方式是页面明示，不是审计追查。审计不记录每次阅读。阅读不属于审计事件。

## 决策 D3 文件夹模型

部门库即默认文件夹。默认文件夹全体部门成员可见。默认文件夹沿用库集合。集合名是 {原生名}__llama__{库标识}。存量文档无须迁移。存量文档天然落在默认文件夹。

项目文件夹是受限文件夹。受限文件夹只有文件夹成员可见。文档只属于一个位置。位置是默认文件夹或某个项目文件夹。移动文档即换位置。移动文档即跨集合调和。调和复用 P1-2 D3 的入口。

受限文件夹集合名需要新规则。集合名是 {原生名}__llama__{库标识}__{文件夹标识}。集合选择即 enforcement 原则不变。检索只查可见文件夹集合。授权钩子按实时文件夹事实再核。无权按不存在处理。

项目只做展示分组。项目分组不单独挂权限。权限只挂文件夹一级。文件夹单层，不嵌套。嵌套需求出现时再立项。

文件夹角色分全权、编辑、只读三档。全权是文件夹内增删文档。全权包括重命名与移动文档。全权不含成员管理。编辑是增改文档内容。编辑不能删文件夹。编辑不能动成员。只读是可读不可改。只读包括检索、问答、预览、下载、导出。只读含下载导出已经由 Owner 确认。

文件夹成员由部门管理员增减。文件夹成员只限本部门成员。增减成员均写审计事件。文件夹角色变更同样写审计。文件夹成员行同样带到期时间。到期规则与 P1-2 一致。

文件夹删除沿用撤部门规则。非空文件夹不让删。删除前先移出文档。每一步均写审计事件。空文件夹删除时删除对应集合。集合删除失败时文件夹删除拒绝。

文件夹创建与删除归部门管理员。项目负责人不建部门文件夹。项目库内文件夹见 D4。

## 决策 D4 项目库模型

项目等于独立项目库。库类型新增 project。库类型 CHECK 需要新迁移。迁移在 kind 列表里加 project。项目库行记录所属部门。所属部门等于创建人部门。项目库标识存入 libraries 表。项目库命名沿用库集合规则。

可见性等于三者并集。并集是公共库加本部门库加我加入的项目库。检索、授权钩子、审计全部复用 P1-1 同一套。不新增 enforcement 机制。集合选择即 enforcement 原则不变。

项目由部门管理员创建。日常创建权在部门管理员。总管理员保留创建权。项目负责人由所属部门管理员任命。负责人人选不限本部门。任命信任来自任命行为本身。

项目负责人管项目成员。项目负责人可加任意在职用户。跨部门正是本功能意义。加人无须总管理员审批。加人均写审计事件。总管理员全局可见。项目负责人不能任命其他项目负责人。跨项目按不存在处理。

项目成员角色与部门角色平行。角色是负责人、编辑、只读三档。负责人拥有项目级权限。编辑可增改项目文档。只读可读不可改。只读范围与文件夹只读一致。角色名用中文称呼。代码值由开发计划定。

项目文档进入分两路。新上传文档由项目负责人认领进项目。认领只针对未分配文档。部门库文档移进项目属于跨库移动。跨库移动走 P1-3 审批。P1-3 落地前只能认领新上传文档。

项目结束沿用撤部门规则。非空项目不让撤。撤前先移出文档。撤前先清掉成员。每一步均写审计事件。归档列为以后选项。归档语义是只读冻结。归档细节列为开放问题。

人事联动清身份时一并清项目身份。离职清零全部身份。身份包括部门身份与项目身份。调岗默认收回旧身份。身份变更即时生效。

项目临时成员沿用 P1-2 规则。成员行带 `expires_at` 字段。项目负责人授临时最长 60 天。项目负责人不能授永久。总管理员与部门管理员授长期不受限。长期包括永久。续期规则与 P1-2 一致。续期在到期前直接改到期时间。续期写续期审计事件。过期删行后只能重新授。

项目库同样支持文件夹。机制与部门库文件夹一致。项目文件夹成员只限项目成员。项目文件夹管理归项目负责人。项目负责人可建删项目文件夹。项目负责人可增减项目文件夹成员。文件夹角色三档同样适用。

## 决策 D5 分流规则

分流规则只有一句话。项目只在一个部门内，用部门文件夹。项目跨部门，用项目库。

文件夹成员只限本部门成员。文件夹不直接加外人。部门文件夹后期需要外人，改走转换路径。转换路径是创建项目库。转换路径还包括跨库移动文档。跨库移动走 P1-3 审批。转换完成后再按项目成员授权。转换前文件夹成员授权不变。

分流规则避免双通道。双通道指文件夹外人与项目库并存。并存会让授权来源难以追溯。审计视图也会出现两种跨部门记录。单通道保持授权来源清晰。

## 决策 D6 审计

文件夹与项目操作全部走 append-only 审计。审计只追加，不修改。审计失败时操作拒绝。规则与 P1-2 D4 一致。PG 路径走同一数据库会话事务。

事件包括建删文件夹。事件包括成员增减与角色变更。事件包括文档进出文件夹。事件包括建项目。事件包括任命项目负责人。事件包括项目成员增减。事件包括项目文档认领。事件包括续期。到期删除本身不写事件。到期证据只剩授予事件。

审计元数据带部门标识。审计元数据带项目标识。项目标识是项目库标识。部门标识是所属部门标识。缺失标识会让部门视图漏掉事件。

部门管理员只看本部门审计。审计范围含本部门项目。项目负责人只看本项目审计。项目负责人看不了其他项目审计。总管理员看全局审计。越权尝试进报表。

永久授权纳入复核清单。复核清单供总管理员定期复查。复核清单覆盖项目永久授权。复核清单覆盖部门永久授权。复核清单覆盖例外永久授权。永久授权没有到期。复核清单是唯一定期复查口子。

## 开放问题

前端文件夹树交互细节。交互包括树展开与收起。交互包括拖拽移动文档。交互包括文件夹内搜索入口。细节由前端切片定。

项目归档语义。归档是只读冻结。冻结范围包括文档与成员。冻结后能否解冻未定。归档审计事件格式未定。细节由开发计划定。

项目成员角色名。建议用负责人、编辑、只读。建议理由是与层级称呼一致。备选是 project_admin、editor、reader。备选理由是与部门角色代码值平行。代码值由开发计划定。Owner 需要确认称呼。

## 非目标

本稿不改 P1-1 已落地的库模型。库标识与集合命名保持不变。只新增 project 库类型。新增类型需要新迁移。本稿不碰 DR-010 数值。本稿不立新的生产装配默认值。本稿不改单智能体架构。本稿不改答案层门禁默认状态。

## 风险与残余

部门管理员全可见与跨部门信任存在张力。外部门成员信任项目范围可见。所属部门管理员可见打破该信任。缓解办法是页面明示。缓解办法还包括审计可见。张力无法完全消除。Owner 已经接受该张力。

集合数增长带来启动开销。文件夹与项目都会新增集合。启动校验集合数量随之增长。触发条件改按总集合数算。触发后走 ADR-016 共享集合迁移。迁移不改 PostgreSQL 权限模型。

项目负责人自由加人的信任假设。信任来自任命行为。信任还来自审计可见。任命不当会放大风险。缓解办法是总管理员复查审计。缓解办法还包括永久授权复核清单。

文件夹移动即跨集合调和。调和复用 P1-2 D3 的入口。调和失败会让文档滞后。滞后损失可用性。滞后不损失保密性。失败状态必须对管理员可见。

项目负责人授权能力随 P1-2 已定规则走。项目负责人授临时最长 60 天。项目负责人不能授永久。续期规则与 P1-2 一致。规则变更时 P1-2 与 P1-4 需同步改。
