# ADR-016：多部门文档库隔离

- 状态：accepted；依据 Owner 2026-10-24 会话决策。
- Accountable：M01；Contributors：M02、M03、M04。
- 基线：main（PR #37 之后）。
- 需求：FR-RBAC-004 要求的 P1 空间与文档 ACL；属权限语义变化，按 SPEC 0.6 登记本 ADR。

## 背景

- MVP 使用共享知识库。前提是只有全员可见且允许外发的文档可进入 ready。
- 该前提无法覆盖多部门场景。各部门需要内部库，且内部库之间相互隔离。
- Owner 2026-10-24 提出多部门隔离设想：一个公共库加多个部门内部库。用户可属多部门。可见范围取并集。总管理员任命部门管理员。部门管理员决定部门内人员权限。
- 本 ADR 把该设想定为最终方案，并给出存储映射与实施顺序。

## 决策

### D1 库模型

- 每篇文档只属于一个库：公共库，或某一个部门库。
- 库标识为 library_id：公共库取 pub，部门库取 dept_id。
- 文档建库时确定归属。库间移动须审批，见 D7。

### D2 成员模型

- 用户与部门为多对多关系。关系表为 memberships，字段为 user_id、dept_id、dept_role。
- 部门内角色为 dept_admin、editor、reader 三档。
- 用户可见库为公共库加所属部门库之并集。权限取并集，不取交集。

### D3 角色与权力边界

- 总管理员为全局角色。权力为建部门、撤部门、任命部门管理员、管理公共库、查看全局审计、裁决跨部门争议。
- 部门管理员只管本部门。权力为加人、移人、设部门内角色、审核本部门文档发布与下线、查看本部门审计。
- 部门管理员管不了其他部门。升不了总管理员。动不了公共库。
- 部门内 editor 可上传。reader 只读。
- 管理员身份不跨部门。校验按（用户，部门）二元组执行，不按是不是管理员一刀切。

### D4 检索过滤

- 服务端检索层执行全部过滤：ready、current、未过期、库属于可见库、结构化 scope。
- 过滤下推到向量层。不得先召回无权向量，再事后过滤。
- 无权文档当作不存在。不返回被过滤数量。不提示存在性。
- 引用点击时重新鉴权。无权则按不存在处理。

### D5 存储映射

- PostgreSQL 为唯一权威源。存 libraries、memberships、文档库归属、审计。行级安全兜底。
- Qdrant 只做派生索引。起步按库分集合：公共库 1 个集合，各部门库各 1 个集合。
- 集合内 chunk 载 library_id、doc_id、version_id、status、acl_version。
- 扩容触发为部门数上百，或集合运维成本显著上升。触发后迁到共享集合加 library_id（is_tenant）加分层分片。不改 PostgreSQL 权限模型。
- 设计不依赖 Qdrant 分层多租户特性。部署版本未验证，不得以该特性为前提。

### D6 文档级例外与临时授权

- 库为粗粒度。单篇文档可再收紧：仅部门管理员可见。
- 单篇文档可临时放宽：共享给某个人或某个部门。须带过期时间。到期自动收回。全程审计。

### D7 发布审批

- 上传不等于发布。部门库文档由 editor 上传后，部门管理员审核才进入 ready。
- 公共库文档由总管理员审批。库间移动须审批，须审计，可回滚。

### D8 人事联动

- 离职清零全部部门身份。调岗默认收回旧部门身份。审批可保留。
- 身份变更即时生效。不得靠月底统一清理。

### D9 历史会话

- 已给出的答案不撤回。重看引用全文时重新鉴权。无权则按不存在处理。

### D10 审计

- 审计分问答、文档版本、权限管理三类。审计记录只追加，不修改。
- 部门管理员只看本部门审计。总管理员看全局审计。越权尝试进报表。

## 实施顺序

- P1-1 库级隔离：memberships、库过滤、Qdrant 按库分集合、审计。
- P1-2 文档级例外与临时授权。
- P1-3 审批流：发布审批、库间移动审批。
- 每步配负向授权测试、跨库隔离测试、下线同步测试。

## 非目标

- 不改单智能体架构。不新增智能体。
- 不改答案层门禁默认状态。默认状态仍随 W3 与 DR-010 定。
- 不冻结 DR-010 数值。不依赖向量库原生三级 RBAC。

## 与现有设计的关系

- FR-RBAC-003 四重授权不变。检索、引用、预览、下载、导出每次重算授权。
- ADR-012 导出授权不变。导出内容不得超出可见库。
- FR-DOC-007 删除语义不变。下线先写 tombstone，再异步清理向量与对象。

## 残余风险

- 向量与库事实不一致。下线须同步清向量。孤儿扫描兜底。检索以数据库实时事实为准。
- 部门管理员误操作。公共库移入须审批。操作可回滚。有审计。
- 临时授权过期清理。到期自动失效。不靠人工记得收回。
- 人事同步延迟。身份变更即时生效。定期对账。
