# ADR-017：文档级例外与临时授权

- 状态：已接受；Owner 2026-10-24 批准。
- Accountable：M01；Contributors：M02、M03、M04。
- 基线：main `38325d4`（P1-1 全部落 main）。
- 需求：FR-RBAC-004 的 P1-2 部分。
- 依据：ADR-016 的 D6；S5 收尾记录的 P1-2 输入清单。

## 背景与范围

P1-1 已经落地库级隔离。文档只归属一个库。库是公共库或部门库。用户可见库是公共库加所属部门库之并集。检索按库分集合执行过滤。管理 API 与审计已经覆盖部门与成员变更。真实 PG 覆盖已经由 CI 永久保证。

P1-2 补两块精细化能力。第一块是文档级例外。单篇文档可以破例共享给库外用户。第二块是临时授权。部门成员身份可以带到期时间。到期自动收回。

本稿不含审批流。上传时选库随 P1-3 设计。发布审批与库间移动审批也随 P1-3 设计。孤儿扫描的生产调用方不在本稿范围。旧单 Qdrant 集合的手动删除属于部署清单项。`authorize` 的 `get_document` 在 PG 下走内存一事，只在出现生产调用方时处理。

本稿与 ADR-016 的 D6 有一处偏离与一处留意。永久例外偏离已由 Owner 签字。签字日期是 2026-10-24。偏离内容见 Q2。D6 提到单篇文档可收紧，例如仅部门管理员可见。本稿的例外只做授予，不做拒绝。收紧语义延后，见 D1 的说明。D6 还提到共享给某个人或某个部门。本稿建模授予给个人与部门。授予给部门见 Q4。

## 决策 D1 文档级例外模型

新表建议名为 `document_exceptions`。字段为文档标识、被授权用户、授予人、授予理由、到期时间、创建时间。文档标识指向文档行。被授权用户指向用户行。授予人记录操作者。授予理由记录业务原因。到期时间为空表示长期。总管理员与部门管理员可授永久。项目负责人不能授永久。

例外只做授予，不做拒绝。可见性保持并集单调。授予一条例外，只增加可见范围，不减少可见范围。拒绝语义用移库解决。把文档移出公共库，或把文档移到另一部门库。移库需要审批，见 P1-3。P1-3 落地之前，收紧路径实际不存在。这是一个诚实说明，不是设计漏洞的掩饰。

例外授予整文档可见性。五处操作与库成员一致。五处是检索、引用、预览、下载、导出。本稿不做按操作拆分。按操作拆分会让授权矩阵翻倍。需求出现时再立项。

执行点分两层，与 P1-1 同构。第一层是可见集合计算。用户可见集合等于可见库文档并例外文档。搜索端点从 Principal 派生该集合，不读请求体。第二层是授权钩子。钩子按实时文档事实再核。无权按不存在处理。查找失败时拒绝，不放行。

第一层的检索机制需要一次诚实修正。P1-1 的检索按库键选择集合。库键选择表达不了按文档授予。直接选中例外文档的所属库集合，会把该库全部节点载入评分语料。未授权向量进入评分，违反 ADR-016 的 D4 下推原则。最终文本仍由钩子拦截，但评分语料已被污染。

修正办法是节点载入时加文档过滤。例外文档的所属库集合只载入已授予的文档节点。其余节点不进入语料。原生路径的 `passes_filters` 同样需要例外文档放行。开发计划必须落实这处检索改动。钩子保持为纵深防御，不做第一层。

授予权力与 S4 一致。部门管理员只授本部门文档的例外。跨部门授予按不存在处理。总管理员不受限。授予人看不到的文档，不能授予例外。授予与撤销均写审计事件。审计元数据带文档所属库标识。部门管理员可以在本部门审计视图里看到本部门文档的例外变更。

例外目标分个人与部门。个人目标指向用户行。部门目标指向部门标识。部门目标读取时展开。展开按目标部门当下成员算。新入职自动可见。离职自动失去。部门目标例外只归总管理员。部门管理员只能授个人例外。

## 决策 D2 临时授权

`memberships` 表新增 `expires_at` 字段。字段类型为带时区时间。空值表示长期。总管理员与部门管理员可授长期。项目负责人授临时最长 60 天。项目负责人不能授永久。

过期判定在读取时执行。可见库计算排除已过期成员。部门管理员范围计算同样排除已过期成员。下一请求即生效。正确性不依赖后台清扫器。清扫器只做卫生用途，可选。清扫器删除过期行或保留过期行，见开放问题 Q3。

过期不产生审计事件。授予事件已经记录到期时间。过期可以由授予事件推导。审计量因此不膨胀。审计追溯需要授予事件加到期时间，两者齐全。

续期在到期前直接改到期时间。续期写一条续期审计事件。事件记录续期人、旧到期、新到期。过期删行后不能续期。过期后只能重新授。续期权限与授予权限一致。项目负责人续期受 60 天上限约束。新到期不得超过续期日加 60 天。

授予临时成员的权力与 S4 一致。部门管理员只管本部门。部门管理员只能授予编辑与读者。部门管理员不能授予部门管理员身份。临时授予同样受此限制。总管理员不受限。总管理员可以授予临时部门管理员身份。

已有成员的临时授予走角色变更路径。新增成员接口遇到已有成员时直接返回，不更新字段。开发计划必须把到期时间更新接到角色变更路径。角色变更路径目前重置授予人与授予时间。到期时间更新的语义需要一并定清。

过期身份即时失效。过期的部门管理员下一请求即失去管理范围。过期的成员下一请求即失去该部门可见库。身份变更不依赖令牌动作。认证每次请求重建 Principal。成员读取每次调用读实时目录。

## 决策 D3 认领向量同步

认领提交后触发 worker 任务。任务调用现有的文档同步入口。同步入口读实时文档库归属。同步入口按库集合调和文档。调和重建目标库集合的节点。调和清扫其余集合的同文档节点。源库删除与目标库重建已经由调和实现。认领同步是接线工作，不是重写调和逻辑。

同步完成前检索可以滞后。方向保持安全。认领改写文档库归属后，授权钩子按新库判定。旧库成员检索时钩子拦截新库文档。新库成员检索时旧库集合不在选择范围。滞后期间无人能通过检索拿到该文档。直接访问按实时库归属立即生效。滞后损失可用性，不损失保密性。

同步失败需要重试并记日志。现有的 worker 同步入口只记日志，不重试，不留状态。本稿要求补重试。失败状态应对管理员可见。具体状态字段留开发计划定。字段可以落在文档行，也可以落在任务记录。开发计划选一种，不两种并存。

认领审计事件已经存在。同步任务的执行结果是否另写审计事件，留开发计划定。最低要求是管理员能看到失败状态。日志只有运维能看，不算管理员可见。

## 决策 D4 审计加固

PG 路径下变更与审计走同一数据库会话事务。部门变更、成员变更、认领变更均适用。变更提交与审计写入同生同灭。审计写入失败时事务回滚。操作拒绝并报错。补偿步骤不再存在。补偿失败导致无审计变更的问题随之消失。

同一事务的前提已经成立。四张表同属一个 PG 库。表是 `libraries`、`memberships`、`documents`、`audit_events`。会话工厂也是同一个。审计只追加规则不受影响。事务只追加审计行，不修改审计行。

实现上需要一次存储边界重构。现在各存储各自开会话。部门管理服务的存储、文档存储、审计存储各用各的会话。同一事务要求 PG 路径把同一个会话传给三处存储。内存路径不受影响。内存存储没有事务概念。内存路径保持现有的补偿行为。

审计分级策略保持不变。`authz.*` 动作属于关键动作。关键动作的审计写入失败必须抛错。一般动作只计数并记日志。同一事务不改变分级。分级决定写入失败时是否抛错。事务决定抛错后变更是否回滚。

## 决策 D5 部门内角色操作矩阵

矩阵分四列。列是读者、编辑、部门管理员、总管理员。行是操作。操作分消费类、管理类、审批类三组。消费类不区分部门内角色。管理类按角色区分。审批类留 P1-3。

消费类操作包括检索、问答、引用、预览、下载、导出。四列全部允许。现行代码已经如此。授权检查只看库可见性，不看部门内角色。授权函数的动作参数目前未使用。矩阵保持这一现状，不假装区分。

上传操作区分角色。编辑与部门管理员可以上传。读者不能上传。总管理员可以上传。上传仍默认落未分配库。认领分发仍走 S4 路径。上传角色门禁是新增项。现行代码没有角色检查。ADR-016 的 D3 写明编辑可上传、读者只读。代码尚未执行这条。本稿把门禁列为 P1-2 实现项。

管理类操作只属于部门管理员与总管理员。成员增减与角色设置属于管理类。部门管理员只管本部门。部门管理员只能授予编辑与读者。认领到本部门属于管理类。部门管理员只能认领到本部门。查看本部门审计属于管理类。部门管理员只看本部门审计。

总管理员独占三项。建部门与撤部门属于总管理员。任命部门管理员属于总管理员。查看全局审计属于总管理员。部门管理员看不了全局审计。部门管理员升不了总管理员。

新增两项属于 P1-2。授予文档级例外属于管理类。授予临时成员属于管理类。两项的权力边界与成员管理一致。部门管理员只授本部门范围。总管理员不受限。

发布审批动作留 P1-3。编辑上传的文档进入 ready 需要审批。审批人是部门管理员或总管理员。审批流设计不在本稿范围。矩阵只预留位置，不定流程。

矩阵与现行代码的不一致已经标出。上传门禁是新增项，不是现行行为。消费类不区分角色是现行行为，矩阵保持不变。授权函数的动作参数未使用，角色门禁落在端点与服务层，不落在可见性检查。

## 已定事项

Q1 已定。最长有效期是 60 天。60 天上限管项目负责人一级。项目负责人授临时最长 60 天。项目负责人不能授永久。总管理员与部门管理员授长期不受限。长期包括永久。

Q2 已定。允许永久例外。永久用空到期时间表示。总管理员可以授永久。部门管理员也可以授永久。允许永久偏离 ADR-016 的 D6。偏离已由 Owner 签字。签字日期是 2026-10-24。一年期可续方案不再采用。永久授权纳入审计复核清单。复核清单供总管理员定期复查。

Q3 已定。到期后行物理删除。删除语义与现行删除成员一致。删除后到期证据只剩授予事件。授予事件记录到期时间。

Q4 已定。例外可以授予给某个部门。部门目标读取时动态展开。展开按目标部门当下成员算。部门目标例外只归总管理员。部门管理员只能授个人例外。部门目标例外写审计事件。审计元数据带目标部门标识。只授个人方案不再采用。

## 非目标

本稿不改 P1-1 已落地的库模型。库标识与集合命名保持不变。本稿不碰 DR-010 数值。本稿不立新的生产装配默认值。本稿不改单智能体架构。本稿不改答案层门禁默认状态。

## 风险与残余

例外与库可见性是双通道。两处来源必须一致。撤销成员身份不能经例外通道漏出。撤销例外不能经成员通道漏出。测试必须覆盖交叉场景。场景包括先授例外后撤成员。场景包括先是成员后撤例外。场景包括例外到期后成员身份仍在。

过期判定依赖服务器时钟。时钟偏移会让边界判定不一致。多实例部署需要同一时间源。时间字段必须带时区。边界测试必须覆盖到期前一秒与到期后一秒。

认领同步期间检索滞后。滞后是可用性损失。滞后不是保密损失。同步失败会让文档长期搜不到。失败状态必须对管理员可见。失败重试必须有上限。上限与告警阈值留开发计划定。

例外授予天然跨越部门边界。跨部门授予是设计用途。授予审计必须对相关部门可见。部门管理员应当看到本部门文档的例外授予。审计元数据必须带文档所属库标识。缺失标识会让部门视图漏掉授予事件。

收紧路径依赖 P1-3 移库。P1-3 落地之前没有收紧手段。公共库文档无法移出公共库。部门库文档无法跨库移动。Owner 应当知晓这个时间窗口。窗口期内的收紧需求只能走下线流程。下线流程是文档删除语义，不在本稿范围。
