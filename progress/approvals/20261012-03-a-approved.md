### 第 3 项：M01 / 安全 ✅

**签认内容**: owner-only、不可见404、停用/重放鉴权、输入/外发与敏感prompt规则

**批准内容**:
1. ✅ 接受 owner-only 策略
   - 只有 Run 的 owner 可以回复澄清
   - 管理员无代理恢复权限

2. ✅ 接受统一 404 策略
   - 非 owner / 不存在 / 不可见统一返回 404
   - 不泄露资源存在性

3. ✅ 接受重放时重新鉴权
   - 同键重放历史回执时检查用户 active/token_version
   - 不能用旧鉴权快照授权重放

4. ✅ 接受输入验证规则
   - 最大长度: 10,000 字符
   - 禁止控制字符（除 `\n` / `\t`）
   - 禁止非 UTF-8 合法字符
   - 超出限制返回 422，不反射用户输入

5. ✅ 接受敏感信息脱敏规则
   - `clarification.prompt` 不包含 reasoning/工具参数/受保护证据
   - 不直接公开 LangGraph interrupt value

**批准时间**: 2026-10-12

### 第 4 项：M03 / 数据基础 ✅

**签认内容**: 单次受理/幂等命名空间、条件事务、执行意图与04-A/DR-011边界

**批准内容**:
1. ✅ 接受幂等命名空间设计
   - `(principal_id, run_id, operation=resume, idempotency_key) UNIQUE`
   - 与创建 Run 的幂等键空间隔离
   - 使用结构化序列化摘要（不是字符串拼接）

2. ✅ 接受单次受理协议
   - 每个 `(run_id, clarification_id)` 最多一个有效受理
   - 使用数据库条件事务（不是进程内锁）

3. ✅ 接受受理事务边界
   - 原子记录：唯一回复/幂等映射 + 状态转移 + 执行意图
   - 事务失败不返回 202
   - HTTP 返回 202 不保证外部调用一定启动

4. ✅ 接受与 04-A 的职责分界
   - 03-A 负责：受理事实 / 幂等回执 / 执行意图持久化
   - 04-A 负责：checkpoint / 租约 / fencing / 崩溃恢复
   - InMemorySaver 只能证明开发夹具行为

**批准时间**: 2026-10-12

### 第 5 项：M05 / ReAct/QA/Run/SSE ✅

**签认内容**: interrupt ID/原thread、状态/回执分离、累计预算/取消、错误优先级

**批准内容**:
1. ✅ 接受 interrupt 机制
   - 服务端生成不可猜测的 `clarification_id`
   - 绑定该 Run 的唯一一次有效 interrupt
   - 使用服务端 `thread_id`（客户端不提供）

2. ✅ 接受状态/回执分离
   - 202 回执中的 `state=resuming` 是历史受理时刻状态
   - 客户端通过 GET/SSE 获取实时状态
   - 同键重放返回同一 receipt，但 request_id 新生成

3. ✅ 接受预算累计行为
   - run_id / message_id 保持原值
   - 预算、rewrite/clarification 次数不重置
   - 原问题 / scope 不改变
   - 截止时间不延长
   - 预算耗尽时安全终止（不发布未验证正文）

4. ✅ 接受取消优先的竞争策略
   - 取消检查在模型/工具/提交边界重复执行
   - 晚到结果不能覆盖终态
   - 使用数据库 fencing/state_version

5. ✅ 接受错误优先级顺序
   - 鉴权/不可见 → 幂等 → 终态/时限 → 状态/澄清ID → 其他门禁
   - 不能通过重试绕过拒绝

**批准时间**: 2026-10-12

### 第 6 项：M08/M09 / Web 客户端 ✅

**签认内容**: GET等待视图、原键重试、202历史回执、错误与SSE消费、旧客户端兼容

**批准内容**:
1. ✅ 接受等待视图 UI 流程
   - GET 获取等待视图（包含 `clarification`）
   - 显示 `clarification.prompt` 给用户
   - 提交到 `POST /api/v1/runs/{id}/resume`

2. ✅ 接受幂等重试逻辑
   - 客户端生成 `idempotency_key`（如 UUID）
   - 网络重试使用同样的 key
   - SSE 重连不会重新提交 resume

3. ✅ 接受 202 历史回执处理
   - 识别 `state=resuming`（历史状态）
   - 不重复显示"正在处理"动画
   - 通过 SSE 或轮询获取实时状态

4. ✅ 接受错误码前端处理
   - 409 RESUME_NOT_ALLOWED → "无法恢复此对话"
   - 409 CLARIFICATION_MISMATCH → "澄清已过期，请重新提问"
   - 422 INVALID_RESUME_REQUEST → "输入无效"

5. ✅ 接受旧客户端兼容策略
   - 旧客户端保持既有行为
   - 旧客户端不启用 Agent 模式
   - 不强制立即升级

**批准时间**: 2026-10-12
