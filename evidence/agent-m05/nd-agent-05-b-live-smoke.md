# ND-AGENT-05-B live 冒烟报告

## 元信息

- 日期：2026-10-21。
- 脚本：`ops/run_agent_live_smoke.py`。
- 模型：DeepSeek 官方 `deepseek-flash`。
- 模型实体：DeepSeek-V4.1-Flash-1017（官方文档注明）。
- 执行方式：云端执行环境经保险库密钥调用官方 API。
- 密钥不落盘、不入仓，报告不含任何凭据信息。

## 范围与口径

- 冒烟共三步，串行执行，每步一次调用。
- 第一步为普通聊天，验证可达性与用量回执。
- 第二步强制指定 `search_knowledge`，验证原生工具调用。
- 第三步回喂工具结果，验证多轮工具协议。
- 工具模式取自 `qa.agent_model.get_tool_schemas`，与生产形状一致。
- 全程关闭 thinking，原因见关键发现第一条。
- 冒烟只证明协议与能力可用。
- 冒烟不等同 Agent 质量评测，不构成 GATE-P0 通过。

## 结果

- 第一步聊天：通过。延迟 8,597 ms。用量 12 token。内容为约定的单字回复。
- 第二步强制工具：通过。延迟 1,671 ms。用量 344 token。模型返回一个工具调用，含调用 id。工具名为 `search_knowledge`。参数为合法 JSON，含 `query` 字段。
- 第三步回喂：通过。延迟 1,445 ms。用量 521 token。模型续调 `read_evidence`，未直接编造答案。
- 总用量 877 token，费用远低于 10 元预算上限。
- 首步延迟明显高于后两步。本报告只记现象。单样本不支撑性能结论。

## 关键发现

- thinking 默认开启时，强制指定工具会被拒绝。官方返回 HTTP 400，原文为「Thinking mode does not support this tool_choice」。故本冒烟全程关闭 thinking。生产图中的 decide 使用自动工具选择，本轮未测 thinking 开启下的自动选择行为。该项留待 05-D 评测覆盖。任何强制指定工具的调用都必须关闭 thinking。
- 回喂检索结果后，模型选择续调 `read_evidence`。该行为符合两工具分工设计，即先检索、再读证据。
- 用量回执完整，三步均返回分项 token。适配器的记账接缝可直接消费该形状。

## 渠道附记

- 随想渠道的模型列表与鉴权已先行验证通过。测试模型 `deepseek-v4.1-flash-1017` 在册，共 24 个模型。
- 该渠道聊天接口从云端出口持续返回 502。三个域名、两个模型、带与不带 `/v1` 前缀，结果相同。普通 HTTPS 出口自测正常。初判为渠道上游对该出口的路由问题。
- 经 Owner 决定，本轮执行改走 DeepSeek 官方 API。官方 `deepseek-flash` 与渠道所测为同一模型实体，评测口径一致。
- 随想渠道保留为开发调试与评测对照，本轮未完成其聊天冒烟。
