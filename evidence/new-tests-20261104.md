## 5. 注意点

1. **18 个用例都是静态断言或 fake 断言**。它们证明配置文本已按要求修改、报错分支文案正确，不证明容器能跑起来。D8-17 只断言了 `Dockerfile.worker` 的安装串含 `http` extra，worker 镜像本轮**未重建**，镜像内 `import fastapi` 是否成功仍未验证。
2. **D8-05 的文案改动只在 fake client 下验证**。`_FakeMinioClient` 与 `_FakeQdrantClient` 用 `ConnectionError` 表示不可达，真实 minio 与 qdrant 客户端在连接失败时抛出的异常类型不同，首次启动的真实行为未复验。
3. **依赖健康用例这次是真跑通过，不是 skip**。本机 5432、9000、6333、6379 四个端口均可达，`test_NFR_OBS_dependency_health_fail_closed_when_compose_down` 断言 `unreachable == []` 通过。但端口可连只等于 TCP 可达，不等于服务健康；真实健康状态请看第 4.4 节与 `docker ps`。
4. **仓库根执行 compose 命令仍会失败**。`docker compose ps` 报 `PIVOT_API_ORIGIN`、`PIVOT_CELERY_BROKER`、`PIVOT_DATABASE_URL`、`PIVOT_MINIO_*`、`PIVOT_ONLINE_QUEUE`、`PIVOT_PARSE_QUEUE`、`PIVOT_WORKER_CONCURRENCY` 缺值，必须先加 `--env-file ops/compose.env.example`。因此[合并后测试清单](../progress/合并后测试清单.md)的任务 1（`docker compose --profile app config` 渲染检查）本轮仍未执行。
5. **只跑了两组，不是全量分组回归**。`ops/run_grouped_tests.py --skip-web` 共 11 组，本轮只跑 `M07-worker` 与 `M11-pipeline`。任务 7 只能记为“部分通过”，不能写通过。
6. **worker 与 web 仍未起**。skip 明细里 compose worker（`127.0.0.1:8001`）与 compose web（`127.0.0.1:3000`）两项因服务不在运行而跳过，与清单任务 2 的“worker `Exited (1)`、web 未构建”一致。D8-17、D8-18 的修复只是让 worker 具备起容器的前置条件，能否起容器要用 `--profile app up worker` 实测。
7. **不改变门禁状态**。本轮无一运行批准，`GATE-P0-001~008` 仍 unverified，D8-04、D8-05、D8-17、D8-18 的端到端部分仍待实测。
