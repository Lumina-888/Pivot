# 联调测试技术文档

## 简介

本文说明 Pivot 在自有环境中部署联调的技术方法。

联调目标是验证 main 最新头在真实依赖下的行为。测试范围以 progress/待测试任务清单.md 为准，包括缺陷 1 至 7 复测、缺陷 2 查询时重建、真实依赖全链路。

本文不覆盖正式验收。GATE-P0-001 至 008 全部未验证，本文测试通过不等于正式验收通过。

## 环境准备

### 硬件与系统

开发机为 Arch / Omarchy 笔记本，项目目录为 ~/Projects/Pivot。

测试中途不合盖休眠，避免服务中断。测试数据只用合成样本和低敏文档，不使用真实企业文档。

### 依赖版本

依赖版本与 2026-11-03 联调报告一致，镜像标签钉死，不用 latest。

- PostgreSQL 为 postgres:16.4，本地端口为 127.0.0.1:5432。
- Qdrant 为 qdrant/qdrant:v1.12.4，本地端口为 127.0.0.1:6333。
- Redis 为 redis:7.4.1，本地端口为 127.0.0.1:6379。
- 对象存储为 pgsty/silo，标签为 RELEASE.2026-09-16T00-00-00Z，本地端口为 127.0.0.1:9000，服务名仍为 minio。

### 启动方法

默认的 docker compose up 只启动 postgres、minio、qdrant、redis 四个依赖服务。

api、web、worker 属于 app profile，启动命令为 docker compose --profile app up。

api 进程为 uvicorn pivot.http.main:app --factory，worker 进程为 python -m pivot_worker，两个进程分离。Celery 入库走 worker 进程，API 进程内存不共享 worker 的索引状态。

## 系统结构

### 检索链路

检索默认走 LlamaIndex 加 Qdrant，BM25 与稠密向量双路召回，RRF 融合，重排器为 BAAI/bge-reranker-v2-m3，嵌入为硅基流动 BAAI/bge-m3。

/search 的 BM25 腿在 PR #74 后改为查询时重建。每次查询从基础集合滚动加载 payload，重建 BM25 索引，并以实时事实回填库与文件夹。QA 腿本来就是每次查询现建 BM25，/search 与 QA 腿模式一致。

/search 的 dense 腿读基础集合 pivot_local，QA 链路读按库集合 pivot_local__llama__库名。认领与移动的调和只更新按库集合，基础集合 payload 的库字段需按实时事实回填，否则 passes_filters 会丢弃合法命中。

### 权限链路

文档读取入口、/search、导出与引用统一走文件夹加例外通道。

受限文件夹内文档对非文件夹成员不可见，返回 404。例外授予的文档对被授予人可读。不可见文档不泄露存在性，统一返回 RESOURCE_NOT_FOUND。

### 对象存储链路

对象存储适配器只用 MinIO Python SDK 的 8 个标准 S3 操作，包括桶存在、建桶、上传、下载、删除、查状态、列对象、预签下载。

Silo 保留 S3 API、MINIO_* 环境变量、server /data 命令、/minio/health/live 健康检查。正式生产对象存储不在本文范围，正式验收环境指定时再走云 S3。

## 测试设计

### 测试数据

测试数据一律使用合成样本。文档、库、文件夹、成员、审批请求均在测试前新建，测试后可重建。

测试库至少包括未分配库、部门库、目标库。测试用户至少包括管理员、目标库成员、非文件夹成员、例外被授予人。

### 测试分组

第一组为缺陷 1 至 7 复测，验证 PR #72 与 PR #73 的修复在真实依赖下生效。

第二组为缺陷 2 查询时重建，验证启动后入库、认领移动、删除、版本取代、重启一致、BM25 腿非空、失败降级、性能记录。

第三组为真实依赖全链路，验证 sync 入库与 Celery 入库、上传解析、认领移动、删除取消、重启全链路、问答金标集。

### 断言方法

BM25 腿断言不只看最终结果里有该文档。断言需确认 BM25 腿非空，且 RRF 融合不是 dense 单路。

删除与版本取代断言需确认 /search 不再返回旧文档。基础集合在删除后仍含旧点，重建时按实时事实过滤是必需项，不是防御性代码。

性能断言需记录查询耗时中位，规模为 16、100、1000 个 chunk。超过该规模前不得宣称可上生产规模。

## 测试步骤

### 部署检查

- 拉取 main 最新头，确认头为 bcb822f4。
- 启动四个依赖服务，确认健康检查通过。
- 启动 app profile，确认 /healthz 正常，/readyz 中 postgres、qdrant、redis 为 true，minio 为 true。
- 确认迁移为单 head，表数为 31。

### 缺陷复测步骤

- 认领与跨库移动后，目标库成员检索文档，管理员与目标库成员结果一致。
- 受限文件夹内文档由非文件夹成员读取，预期为 404。例外授予的文档由被授予人阅读，预期可读。
- 内容去重跨库命中时，不静默丢弃目标库，不回显无权限文档标识，不绕过发布审批。
- 示例配置启动 app profile，确认 BM25 参数与公开下载地址通过校验。
- Silo 桶创建、上传、读取、预签下载四步均通过。

### 查询时重建步骤

- 启动后新入库，不重启，/search 的 BM25 腿命中新文档。
- 认领与移动后，不重启，/search 立即反映新库归属。
- 删除后，/search 不再返回该文档。版本取代后，旧版本 chunk 不再返回。
- 重启前后，同一查询结果一致。
- 滚动加载或重建失败时，dense 腿仍能服务，整次检索不失败。

### 全链路步骤

- sync 入库后，不重启，/search 与问答均能命中。
- Celery 入库后，不重启 API，/search 与问答均能命中。
- 上传、解析、认领、移动、删除、取消、重启全链路各跑一次。
- 问答金标集跑一遍，记录引用错误率、过期规则命中、租约 fencing、预算对账四项实测数字，不编造。

## 结果记录

结果按 progress/待测试任务清单.md 中的记录表填写。

失败项附日志与复现步骤，区分回归与环境问题。环境问题包括端口占用、镜像拉取失败、合盖休眠、配置缺失。

## 故障处理

- 依赖服务未启动时，先查 docker compose ps 与健康检查，再查端口占用。
- API 启动失败时，先查示例环境变量是否齐全，再查数据库连接与 Qdrant 连接。
- /search 命中缺失时，先查基础集合 payload 的库字段，再查实时回填逻辑，最后查 passes_filters 的范围判断。
- Silo 拉取失败时，确认镜像标签为 RELEASE.2026-09-16T00-00-00Z，确认 Docker 代理配置为本机设置，不改仓库配置。
